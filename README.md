# بازار شاهین 🦅

مارکت‌پلیس رزرو آنلاین خدمات (آرایشگاه، ناخن‌کار، اسپا، باشگاه، خالکوبی و ...) — الهام‌گرفته از Fresha، با بک‌اند و پایگاه‌داده واقعی.

## ویژگی‌ها

**احراز هویت مدرن (سه نقش مجزا)**
- مشتری: ثبت‌نام/ورود با ایمیل + رمز عبور
- ارائه‌دهنده: ثبت‌نام/ورود با شماره تلفن + رمز عبور
- مدیر سیستم: ورود با ایمیل + رمز عبور + **احراز هویت دو مرحله‌ای اختیاری (2FA با TOTP)**
- نمایش/مخفی‌سازی رمز عبور، نوار قدرت رمز، اعتبارسنجی لحظه‌ای فرم‌ها، پیام خطای اختصاصی هر فیلد
- نشست امن: توکن دسترسی کوتاه‌مدت + تازه‌سازی خودکار در پس‌زمینه (کاربر هرگز به‌خاطر انقضای توکن بیرون پرت نمی‌شود)
- محدودیت نرخ تلاش ورود/ثبت‌نام برای جلوگیری از حملات Brute-Force

**سمت مشتری (داشبورد کامل)**
- نمای کلی: نوبت‌های پیش‌رو، تعداد علاقه‌مندی‌ها
- نوبت‌های من: فیلتر پیش‌رو/انجام‌شده/لغوشده، لغو نوبت، ثبت نظر و امتیاز پس از انجام نوبت
- علاقه‌مندی‌ها: ذخیره و حذف کسب‌وکارهای موردعلاقه (❤️ روی صفحه هر کسب‌وکار)
- پروفایل: ویرایش نام/تلفن/رمز عبور
- امکان رزرو مهمان (بدون ثبت‌نام) هم‌چنان با پیگیری با شماره تلفن باقی مانده

**سمت ارائه‌دهنده (داشبورد کامل)**
- کسب‌وکار جدید پس از ثبت، در وضعیت «در انتظار تأیید مدیر» قرار می‌گیرد
- نمای کلی آماری، مدیریت نوبت‌ها (تأیید/لغو/انجام‌شد)، خدمات، پرسنل، نظرات دریافتی، پروفایل
- بنر وضعیت (در انتظار تأیید / ردشده / معلق) در بالای داشبورد

**سمت مدیر سیستم (داشبورد کامل مدیریتی)**
- نمای کلی: آمار کل پلتفرم، درآمد، توزیع دسته‌بندی‌ها
- کسب‌وکارها: تأیید / رد / تعلیق هر کسب‌وکار با فیلتر وضعیت
- **دسته‌بندی‌ها (تب اختصاصی، CRUD کامل)**: افزودن، ویرایش درجا، حذف با **انتقال اجباری** کسب‌وکارهای وابسته به دسته‌بندی دیگر قبل از حذف (مودال اختصاصی)
- مشتریان: مشاهده و مسدود/رفع مسدودی
- نوبت‌های پلتفرم: مشاهده کل نوبت‌ها با فیلتر وضعیت/تاریخ
- مدیران: افزودن/حذف مدیر جدید (حداقل یک مدیر همیشه باقی می‌ماند)
- امنیت حساب: فعال/غیرفعال‌سازی 2FA با نمایش QR کد و کلید دستی

## پشته فنی

- **زبان:** TypeScript (حالت strict کامل) با ماژول‌های ES (ESM)
- **بک‌اند:** Node.js (نسخه ۲۲.۵ به بالا) + Express، با **معماری لایه‌ای**: Route → Controller → Service → Repository
- **دیتابیس:** SQLite از طریق ماژول داخلی `node:sqlite` — بدون نیاز به کامپایلر/Visual Studio Build Tools (فاز بعدی: مهاجرت به PostgreSQL)
- **احراز هویت:**
  - توکن دسترسی (Access Token) کوتاه‌مدت (۱۵ دقیقه پیش‌فرض) با JWT
  - توکن تازه‌سازی (Refresh Token) با **چرخش** (rotation) — در کوکی `HttpOnly` + `Secure` + `SameSite=Strict` ذخیره می‌شود، نه در localStorage
  - تازه‌سازی خودکار در فرانت‌اند: وقتی توکن دسترسی منقضی شود، بدون نیاز به ورود دوباره، به‌صورت شفاف تازه‌سازی می‌شود
  - احراز هویت دو مرحله‌ای (2FA) با TOTP برای مدیران — سازگار با Google Authenticator و مشابه، بدون نیاز به سرویس خارجی
  - `bcryptjs` (خالص JS) برای هش رمز عبور — عمداً به‌جای نسخه native انتخاب شده تا نیاز به Visual Studio Build Tools نباشد
- **محافظت‌های امنیتی:**
  - `helmet` با Content-Security-Policy سفارشی‌شده (هدرهای امنیتی HTTP)
  - `express-rate-limit`: محدودیت عمومی روی همه API + محدودیت سخت‌گیرانه‌تر روی مسیرهای ورود/ثبت‌نام (محافظت در برابر Brute-Force)
- **اعتبارسنجی env:** با `zod` و `dotenv`
- **لاگ‌گیری:** `winston` — خروجی رنگی در کنسول + فایل‌های `logs/error.log` و `logs/combined.log`
- **کیفیت کد:** ESLint (flat config) + Prettier + Husky (بررسی خودکار قبل از هر commit)
- **فرانت‌اند:** HTML/CSS/JavaScript خالص (بدون فریم‌ورک)، تک‌صفحه‌ای با روتینگ مبتنی بر هش، کاملاً راست‌چین و فارسی

> 📋 این نسخه **فاز صفر** (زیرساخت: TypeScript + معماری لایه‌ای + لاگ‌گیری) و **فاز یک** (امنیت: Rate Limiting + Helmet + Refresh Token + 2FA) از نقشه‌راه ارتقاء را کامل پیاده‌سازی کرده است. فازهای بعدی (OTP پیامکی واقعی، مهاجرت PostgreSQL+Prisma، Redis، پرداخت آنلاین، فرانت‌اند React) در انتظار تأیید و اولویت‌بندی هستند.

## اجرا

> پیش‌نیاز: Node.js نسخه ۲۲.۵ یا بالاتر (برای پشتیبانی از `node:sqlite`). نسخه خود را با `node -v` بررسی کنید.

```bash
npm install
cp .env.example .env      # فقط بار اول — متغیرهای محیطی را می‌سازد (مقادیر پیش‌فرض برای توسعه کافی‌اند)
npm run seed               # پر کردن دیتابیس با داده‌های نمونه (فقط بار اول لازم است)
```

### متغیرهای محیطی مرتبط با امنیت (در `.env`)
| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `JWT_ACCESS_EXPIRES_IN` | `15m` | عمر توکن دسترسی |
| `JWT_REFRESH_EXPIRES_DAYS` | `30` | عمر توکن تازه‌سازی (روز) |
| `TEMP_2FA_TOKEN_EXPIRES_IN` | `5m` | عمر توکن موقت بین مرحله اول و دوم ورود مدیر |
| `RATE_LIMIT_WINDOW_MIN` | `15` | بازه محدودیت نرخ درخواست (دقیقه) |
| `RATE_LIMIT_MAX` | `300` | حداکثر درخواست عمومی در بازه |
| `AUTH_RATE_LIMIT_MAX` | `8` | حداکثر تلاش ورود/ثبت‌نام در بازه |

> ⚠️ در محیط production حتماً `JWT_SECRET` را به یک مقدار طولانی و تصادفی تغییر دهید و `NODE_ENV=production` را تنظیم کنید (کوکی refresh فقط در حالت production پرچم `Secure` می‌گیرد که نیازمند HTTPS است).

**برای توسعه** (اجرای مستقیم TypeScript با ری‌استارت خودکار روی تغییر فایل):
```bash
npm run dev
```

**برای اجرای نسخه build‌شده** (شبیه‌سازی production):
```bash
npm run build     # کامپایل TypeScript به JavaScript در پوشه dist/
npm start          # اجرای نسخه کامپایل‌شده
```

سپس به آدرس `http://localhost:3000` بروید.

هنگام اجرا ممکن است پیام زیر را ببینید — کاملاً طبیعی است و نشان‌دهنده خطا نیست:
```
ExperimentalWarning: SQLite is an experimental feature and might change at any time
```

### سایر اسکریپت‌ها
```bash
npm run lint      # بررسی کیفیت کد با ESLint
npm run format    # فرمت‌دهی خودکار با Prettier
```
اگر پروژه را با `git init` به یک مخزن Git تبدیل کنید، هوک Husky در `.husky/pre-commit` پیش از هر commit به‌طور خودکار `tsc --noEmit` و `eslint` را اجرا می‌کند تا کد نامعتبر commit نشود.

## ساختار پروژه (معماری لایه‌ای)

```
shahin-market/
├── src/
│   ├── server.ts                  # نقطه ورود — اجرای مهاجرت‌ها و شروع سرور
│   ├── app.ts                     # ساخت اپلیکیشن Express و اتصال روت‌ها
│   ├── seed.ts                    # داده‌های نمونه
│   ├── config/
│   │   ├── env.ts                  # اعتبارسنجی متغیرهای محیطی با zod
│   │   └── logger.ts               # پیکربندی winston
│   ├── types/index.ts              # تایپ‌های مشترک (Category, Business, Booking, RefreshToken, ...)
│   ├── db/connection.ts            # اتصال node:sqlite + مهاجرت جدول‌ها (شامل refresh_tokens و ستون‌های 2FA)
│   ├── repositories/               # لایه دسترسی خام به داده (یک فایل به‌ازای هر جدول)
│   ├── services/
│   │   ├── auth.service.ts          # ثبت‌نام/ورود + جریان 2FA مدیر
│   │   ├── session.service.ts       # صدور و چرخش access/refresh token
│   │   └── admin.service.ts         # شامل راه‌اندازی/تأیید/غیرفعال‌سازی 2FA
│   ├── controllers/                # هندلرهای نازک HTTP — فقط صدا زدن سرویس‌ها
│   ├── routes/                     # تعریف مسیرهای Express و اتصال میان‌افزار نقش
│   ├── middleware/
│   │   ├── auth.middleware.ts       # احراز هویت JWT نقش‌محور
│   │   ├── rateLimit.middleware.ts  # محدودیت نرخ عمومی و ورود/ثبت‌نام
│   │   ├── error.middleware.ts      # مدیریت متمرکز خطا
│   │   └── requestLogger.middleware.ts
│   └── utils/                      # errors.ts، asyncHandler، jwt (access + 2FA موقت)، token (refresh هش‌شده)، cookies، validators
├── dist/                           # خروجی build (تولیدشده توسط tsc، در git نادیده گرفته می‌شود)
├── public/                         # فرانت‌اند (HTML/CSS/JS خالص)
│   ├── index.html
│   ├── css/style.css
│   └── js/{api.js, app.js}
├── logs/                           # فایل‌های لاگ (تولیدشده توسط winston)
├── tsconfig.json
├── eslint.config.js
├── .prettierrc
├── .env.example
└── .husky/pre-commit
```

**جریان یک درخواست معمولی:** `route` درخواست را به `controller` می‌سپارد ← `controller` ورودی خام Express را می‌گیرد و `service` را صدا می‌زند ← `service` منطق تجاری و اعتبارسنجی را اجرا می‌کند و از `repository` برای خواندن/نوشتن داده استفاده می‌کند ← خطاها با کلاس‌های `AppError` (در `utils/errors.ts`) پرتاب می‌شوند و به‌صورت متمرکز در `error.middleware.ts` مدیریت و لاگ می‌شوند.

## نقشه پایگاه‌داده

- `categories` — دسته‌بندی کسب‌وکارها
- `owners` — صاحبان کسب‌وکار (احراز هویت با شماره تلفن)
- `customers` — مشتریان (احراز هویت با ایمیل)
- `admins` — مدیران سیستم (احراز هویت با ایمیل؛ شامل `totp_secret` و `totp_enabled` برای 2FA)
- `businesses` — کسب‌وکارها (هر کدام به یک owner و یک category متصل؛ دارای وضعیت pending/active/rejected/suspended)
- `services` — خدمات هر کسب‌وکار
- `staff` — پرسنل هر کسب‌وکار
- `bookings` — رزروهای مشتریان (به‌صورت اختیاری به حساب customer متصل می‌شود؛ رزرو مهمان هم پشتیبانی می‌شود)
- `reviews` — نظرات مشتریان (به نوبت انجام‌شده متصل است)
- `favorites` — کسب‌وکارهای موردعلاقه هر مشتری
- `refresh_tokens` — توکن‌های تازه‌سازی نشست (فقط هش SHA-256 ذخیره می‌شود، هرگز مقدار خام)
